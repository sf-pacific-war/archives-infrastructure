Design Principles and Architecture

Design document for the digital collections and reading-room program: preservation, collections truth, interoperability, public discovery, and AI-derived layers work separately and together.

Findings

Trusted collection records, cross-institution discovery, and governed AI are baseline conditions for the project.

Historical evidence management, publication scope, external-source links, and one trusted research entry point determine the reliability of the digital archives program.

Core conditions include release policy, citable source links, explainable discovery methods, and standards-aligned data that can grow with the collection.

Trusted records

Every public record should show source, holding institution, rights boundary, and review status. This is a baseline condition for the reading room.

System Stack

Five layers: preservation, collections truth, interoperability, discovery, and AI.

Each layer carries a distinct responsibility: preservation evidence, governed records, cross-institution exchange, public access, and AI-derived capabilities do not replace one another.

Lower layers preserve truth and evidence. Upper layers extend access and interpretation.

AI

AI enrichment and retrieval

Translation, summaries, entities, topic suggestions, embeddings, and RAG answers.

Derived, labeled, reviewable, and rebuildable from source evidence.
D

Discovery and digital reading room

Browse, search, filters, detail pages, bilingual display, public-only publication rules.

Uses approved records; never publishes unknown-rights or unreviewed material by default.
I

Interoperability and aggregation

NARA, university archive, JACAR, DPLA/EDM-style mappings, source IDs, link-out strategy.

External records stay provenance-rich instead of being flattened into local-only descriptions.
C

Collections metadata and archival description

Canonical record identity, hierarchy, source text, rights, review state, authorities, topics.

The system of record for what the institution claims and publishes.
P

Preservation and storage evidence

Master files, checksums, preservation metadata, accession context, processing events, storage locations.

Long-term stewardship layer; not GitHub, not public web derivatives.
Metadata, Relationships, Retrieval

Hybrid retrieval constrained by structured facts.

Deterministic structured metadata governs access, dates, rights, hierarchy, and source identity. Relationship modeling keeps people, places, events, records, and files linked. On top of that structure, hybrid retrieval combines exact search, lexical search, semantic retrieval, and reranking.

Metadata determines what the system can safely claim. Retrieval determines how researchers can find it without losing evidence.

Metadata strategy

We use a small, stable canonical metadata model for internal consistency, while mapping to and retaining key source metadata where permitted.

Example

An oral history interview can reference a letter and a photograph about the same event in Kunming, 1944.

All remain linked to the event, place, person, collection, and rights state instead of becoming isolated search hits.

1. Exact and fielded search

Best for identifiers, names, dates, rights state, collection filters, and known-item retrieval.

2. Lexical search

BM25-style retrieval remains very effective for rare names, historical phrasing, acronyms, and precise quotations.

3. Semantic retrieval

Vector retrieval can connect multilingual wording, indirect references, and conceptually related materials across collections.

4. Reranking and evidence packages

Final ranking should combine relevance, authority signals, and explicit evidence such as source record, page, region, or timestamp.

Result: trustworthy, explainable discovery constrained by structured facts and explicit evidence.

Reference Roles

Documents, data systems, and public access carry different roles.

Planning documents, schema drafts, research notes, and HTML pages express institutional intent. Governed records, preservation files, and public access should be carried by their own systems.

The comparison below distinguishes reference materials from long-term archival responsibilities.

Area Reference material Long-term responsibility Interpretation
Program framing Planning docs, scope boundaries, track definitions Institutional direction, review roles, decision context Defines the boundary and vocabulary of the program.
Canonical records Archival record schema draft and sample JSON Collections management data store or governed export pipeline Defines how local and external records align in one canonical model.
Digital assets Only small samples and references Preservation storage, access derivatives, fixity, rights-controlled delivery Defines what belongs in preservation storage and what belongs in public delivery.
Interoperability Research notes and future crosswalk folders DPLA/EDM, Dublin Core, EAD, IIIF, OAI-PMH, API or export profiles Defines how partner-held records remain linkable and provenance-rich.
Public access Reading-room requirements and presentation notes Website or app with search, facets, detail pages, public-only rules Defines how approved records become discoverable to researchers and visitors.
AI layer Principles and derived-content fields Translation, summary, retrieval, review, and model provenance Defines how AI extends access while remaining subordinate to source truth.
Layered Sequence

The plan grows by layer: stabilize records first, then expand access and AI.

The reading room can begin with lightweight, approved data while preserving clear positions for preservation packages, IIIF, external APIs, search indexes, and reviewed AI layers.

Capabilities accumulate from source truth to public access.

Phase 0

Program boundary

Define the four tracks, their boundaries, and excluded parallel products.

Phase 1

Canonical model

Align memorial hall, NARA, and university records within one governed schema.

Phase 2

Reading room

Provide browse, search, filters, bilingual fields, detail views, and public-only display.

Phase 3

Rights and preservation links

Add review status, preservation references, and crosswalk validation.

Phase 4

Federation and AI

Add external APIs, IIIF/OAI-PMH where useful, embeddings, and reviewed AI enrichments.
