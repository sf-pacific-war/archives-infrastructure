比较研究报告

面向 WWII Pacific War Memorial Hall 的数字馆藏计划，本报告整理同行机构、 academic 与 digital humanities 实践、专业标准和开源工具中的相关参考。

Comparative Cases

同行实践表明，数字馆藏项目通常同时服务保存、公众访问和研究复用。

DPLA、Europeana、NARA、Library of Congress、UNT、昭和馆、Densho、JACAR 和 Stanford 的相关项目显示， 可持续数字馆藏依赖清晰来源、标准化描述和明确的合作边界。

对本项目的启发是：外部来源不必全部迁入本地系统，但必须保留 source semantics， 并通过 metadata aggregation、API、stable identifiers 和清晰 attribution 进入统一发现体验。

DPLA

大型美国 cultural heritage aggregation 模式，把图书馆、档案馆、博物馆和地方 hub 的 metadata 汇入统一发现入口。技术上最值得看的是 hub/provider 分层、Metadata Application Profile、source attribution 和面向 reuse 的聚合数据结构。

DPLA MAP Discovery

Europeana

欧洲级文化遗产聚合平台，把多国机构资料组织为跨语言、跨机构发现系统。技术上可以参考 Europeana Data Model、provider/data provider 区分、rights statement、linked-data oriented aggregation 和统一 API。

Europeana EDM APIs

NARA Catalog

美国国家档案馆的公共检索系统，适合参考 national-scale records、series、file units、items 和 digital objects 的公开发现方式。技术上重点看 NAID、Catalog API、source-native identifiers、digital object link-out 和 metadata harvesting。

NARA API Catalog

国家级 digital collections 与 item API 参考，覆盖图像、文本、音频、影像、地图和展览型 collection。技术上可参考稳定 URL、JSON API、IIIF image service、rights/access note 和 collection-level browse。

Metadata / Field Review

字段标准不是导出清单，而是三层检索设计：通用发现字段、Pacific War 专题字段和 authority records。

这一层放在 archive cases 后面，方便 reviewer 在比较 UNT、昭和馆、DPLA、Europeana、NARA 和 LoC 时， 同步判断每个字段属于哪一层、如何进入 search index、facet、引用、导出、保存和长期迁移。

建议本项目采用 local canonical profile：DCMI 负责跨馆藏通用发现，Pacific War 字段负责专题研究维度，authority records 负责把人物、地点、部队、战役和主题做成可复用、可消歧、可关联的实体。

1 通用发现层

Dublin Core / DCMI Terms 提供跨系统最稳定的字段语言：title、creator、date、type、subject、spatial、rights、identifier、source 和 relation。它们不只是 export mapping，也应该直接进入关键词检索、基础 facet、排序、引用和跨机构 aggregation。

2 Pacific War 专题 / 类型扩展层

通用字段无法表达所有研究问题，所以 local profile 需要加入 theater、campaign、battle / operation、military unit、occupation context、POW camp、civilian group、language、source community 和 sensitivity / access context 等专题字段，并吸收不同材料类型、保存和媒体呈现所需字段。

3 Authority / 规范实体层

Authority model 不是一组普通标签，而是一套可复用实体记录。档案 item 应引用 person、organization、place、unit、event 和 subject 的 authority ID，并保留 preferred label、别名、多语言形式、外部 URI 和关系。

下面的标准卡片用同色标签回连到上方三层；同一标准可能服务多层，这里按 reviewer 的首要用途归类。

Project Model

项目由六项机构能力共同支持。

记录维护、公开批准、合作来源管理、AI 质量控制、长期保存和公共访问分别承担不同责任。

跨机构发现让多个来源在统一入口中被检索、比较和引用，同时保留各自来源身份。

1. Collection Governance

定义 canonical record、rights policy、publication approval 和 takedown process，保证公开内容可解释、可维护。

2. Federated Discovery

连接本馆、NARA、大学档案和其他来源，通过 crosswalk 与 attribution 呈现统一发现，而不抹平来源差异。

3. Public Reading Room

为公众、研究者、学生和馆内工作人员提供可信入口：浏览、检索、过滤、引用、打开来源。

4. Preservation Assurance

将长期保存责任作为机构承诺管理：保存级材料、版本、完整性检查和可迁移性需要独立于展示层。

5. AI Review Controls

AI 输出必须被标注为 derivative content，并回到具体证据、来源记录和人工审核状态。

6. Partnership Terms

对外合作应能清楚回答：我们能接收什么、公开什么、链接什么、引用什么，以及如何尊重来源机构。

比较研究报告：用于整理参考来源、明确项目范围，并支撑后续系统评估。

Comparative Cases

Peer practice indicates that digital collection programs commonly support preservation, public access, and research reuse together.

DPLA, Europeana, NARA, the Library of Congress, UNT, Showakan, Densho, JACAR, and Stanford's related work show that sustainable digital collections depend on clear sources, standardized description, and defined partnership boundaries.

The key lesson for this project: external sources do not all need to move into one local system, but they must retain source semantics and enter a unified discovery experience through metadata aggregation, APIs, stable identifiers, and clear attribution.

Metadata / Field Review

Field standards are not an export checklist; they define three discovery layers: general fields, Pacific War domain fields, and authority records.

This layer sits directly under the archive cases so reviewers can compare UNT, Showakan, DPLA, Europeana, NARA, and LoC while checking which layer each field belongs to and how it supports search indexes, facets, citation, export, preservation, and long-term migration.

Recommended approach: keep a local canonical profile. DCMI supplies cross-collection discovery, Pacific War fields supply domain research dimensions, and authority records make people, places, units, battles, and subjects reusable, disambiguated, and linkable.

1 General Discovery Layer

Dublin Core / DCMI Terms provide the most stable cross-system field language: title, creator, date, type, subject, spatial coverage, rights, identifier, source, and relation. They should not be export-only mappings; they should feed keyword search, core facets, sorting, citation, and cross-institution aggregation.

2 Pacific War Domain / Type Extension Layer

General fields cannot answer all research questions. The local profile should add domain fields such as theater, campaign, battle / operation, military unit, occupation context, POW camp, civilian group, language, source community, and sensitivity / access context, while also absorbing type-specific, preservation, and media-presentation fields.

3 Authority / Entity Layer

The authority model is not a tag list. It is a set of reusable entity records. Items should point to authority IDs for people, organizations, places, units, events, and subjects, with preferred labels, aliases, multilingual variants, external URIs, and relationships.

The standards below use matching layer tags to show how they connect back to the three headers. A standard may support multiple layers; this map classifies it by the reviewer's primary use.

Authorities: names, places, subjects

Authority records determine discovery quality. Reviewers should check whether people, organizations, places, subjects, events, military units, and objects are managed as reusable entities rather than scattered free text; each entity should carry preferred labels, alternate labels, source vocabularies, authority URIs, language variants, local notes, and structured relationships. Available Systems Overview

Available systems should be selected by responsibility: collection management, public discovery, repository infrastructure, preservation workflow, vocabulary control, and storage are different layers.

This table includes both open-source software and commercial/hardware storage options. Open source does not mean zero cost; cloud storage is not an archival system by itself and still needs metadata, fixity, backup, and access governance.

Rough cost uses public US pricing checked on 2026-08-23. Cloud estimates exclude taxes, egress, API operations, retrieval, replication, support, data migration, and staff time unless noted.

Project Model

The project is supported by six institutional capabilities.

Record maintenance, public release, partner-source management, AI quality control, preservation, and public access each carry distinct responsibilities.

Cross-institution discovery keeps source identity visible while bringing multiple holdings into one research path.

1. Collection Governance

Define canonical records, rights policy, release approval, and takedown process so public content remains explainable and maintainable.

2. Federated Discovery

Connect local holdings, NARA, university archives, and other sources through crosswalks and attribution without flattening source differences.

3. Public Reading Room

Give public users, researchers, students, and staff one trusted entry point for browsing, searching, filtering, citation, and source access.

4. Preservation Assurance

Manage preservation responsibility as an institutional commitment that remains independent from the public presentation layer.

5. AI Review Controls

Label AI outputs as derivative content and tie them to evidence, source records, and human-review state.

6. Partnership Terms

Clarify what the institution can receive, publish, link, cite, and attribute when working with partner-held records.

Comparative research report for reference review, scope definition, and later system evaluation.
